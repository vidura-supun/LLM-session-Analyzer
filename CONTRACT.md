# LLM session Analyzer implementation contract

Standalone offline HTML + classic JS + CSS, no dependencies, no server required, no network requests. All imported data remains in browser memory. Open index.html directly. Treat every imported string as untrusted text; never render imported HTML. Files under neighboring directories are read-only fixtures, never copy private content into source/demo/docs.

Parser owns parser.js and parser.test.cjs. UI owns index.html, app.js, styles.css, demo.js. Main architect owns README.md and integration review. Use apply_patch for edits.

parser.js exposes globalThis.SessionParser (and module.exports in Node):

- parseJSONL(text, sourceName) => {source, records: [{raw,line}], warnings: [{source,line,message}], totalLines}. Blank lines skipped; BOM and CRLF supported; malformed lines reported, remaining lines retained. Reject non-object records. Keep originals.
- parseMemory(text, sourceName) => {id,source,name,description,originSessionId,content,body,metadata}. Read basic YAML front matter without dependencies including nested originSessionId. Keep all text.
- buildWorkspace(parsedFiles, memories=[]) => {sessions, memories, warnings}. Each session: {id,title,cwd,branch,models:[],sources:[],events:[],agents:[],memories:[],stats,startTime,endTime}. Each event: {id,kind,title,text,timestamp,sessionId,agentId,source,line,uuid,parentUuid,model,isError,raw,tool?}. kind is one of prompt, assistant, thinking, tool, result, system. Tool: {id,name,input,command,status,result,resultSource,resultLine,resultRaw,durationMs,questionInteraction?}; status success/error/pending. AskUserQuestion interactions preserve question headers, prompts, single/multi-select settings, option labels/descriptions/previews, structured answers, annotations, selection matches, and answered/rejected/unanswered/pending state from toolUseResult. Tool results pair with calls by session+agent+tool_use_id; paired result content displayed inside tool event, not duplicated result event. Orphan tool results use result kind. Event raw is whole source record, not block. Source and line provenance for call AND result. Preserve unknown events as system. Redacted thinking labelled unavailable, not reconstructed. Metadata/user isMeta messages are system, not human prompt. File-history and other book-keeping remain system events. Each content block becomes distinct event with stable id. Models/branch/cwd captured; metadata titles preferred over first prompt fallback. Sidechain agentId explicit or inferred from agent-\*.jsonl path. Main session identity from sessionId/session_id with filename fallback. Agents are string IDs (main = 'main').
- stats: {prompts,assistant,thinking,tools,errors,events,inputTokens,outputTokens,cacheReadTokens,cacheWriteTokens}; token usage deduplicate streamed assistant blocks by message.id+agent, take per-field max for each message. Do not add cached input to inputTokens. Explain these are recorded counts, not billing.
- memory links to sessions by explicit originSessionId only; workspace memories remain accessible even if unmatched. A memory is current context, not proof it was present during session.
- events retain file order; if multiple source logs merge, stable timestamp order with untimed events anchored to adjacent source records (do not send all metadata arbitrarily to start/end). Branches recorded, not pretend one canonical conversation. UI labels timeline as recorded events and can filter agents.

UI requirements: elegant light analysis workbench, muted cream background, dark ink/nav sidebar, teal accents; meaningful empty state, synthetic demo button. Multi-file input (.jsonl,.md), folder picker including subdirectories, drag/drop files. Skip unrelated files and agent .meta.json sidecars. Multiple imports additive; same source path replaces prior import; explicit clear. Main sidebar sessions + search, active session stats, timeline/memory tabs. Timeline full-text search including tool inputs and results; kind toggles, tool selector, agent selector, errors-only; reset filters; matched count. Search results provide previews and a Go to result action that restores the normal timeline, opens the correct page, focuses the event, and exposes surrounding context. All displayed valid timestamps use UTC `YYYY-MM-DD HH:mm:ss UTC`. System records start hidden; orphan results share the Tools filter. Show prompts/assistant clearly, thinking collapsed by default, tool command preview and expandable input/output/raw/provenance, error/pending badge. AskUserQuestion events render readable question cards, choices, chosen/custom answers, and rejected/unanswered states. Truncate long previews only with access to full content. Paginate/limit rendering for large imports. Export filtered normalized events JSON and raw import warnings accessible. Save PDF builds a local print report containing every matching event across pages, readable tool input/results and questions, plus linked memory, then opens the native browser dialog for Save as PDF. Session metadata summary + jump to prompts across pages. Memory pane readable text/front matter and origin session links. Responsive and accessible labeled controls, keyboard functionality, visible aria-live status. No code executes from imported records. No automatic external image/link fetches. No network fonts or CDN. Local file:// support requires classic script tags.

Demo entirely fictional and covers prompt, thinking, tools success/error/pending, assistant, linked memory and side agent. Tests use Node built-in test runner, check malformed JSONL, provenance, tool pairing, token dedup, agent collisions, missing thinking, unknown records, unlinked memory, real local fixtures (aggregate only). No private data in committed demo or test fixture snapshots.
